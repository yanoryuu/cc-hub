# CC Hub 要件定義書 v1.0

> 複数の Claude Code セッションを 1 つのデスクトップアプリに集約し、worktree プール・ブランチ/PR 管理・スマホ連携(CC Remote)を提供する。
> 作成: 2026-10-10

## 0. 決定事項

| 項目 | 決定 |
|---|---|
| アーキテクチャ | **共通デーモン方式**:常駐 Hub デーモン(Node.js)がセッション PTY・worktree・イベントを一元管理。デスクトップ UI とスマホ UI はそのクライアント |
| 技術スタック | **Electron + React**(node-pty / xterm.js を CC Remote から流用) |
| 監視対象 | **アプリ起動セッションは完全制御 + 外部起動セッションは読み取り専用で表示** |
| リポジトリ登録 | **GitHub の URL を入力すると自動でクローン**し、プール対象にする |
| worktree プール | **待機数 3 本を維持**。足りなくなれば自動で増やし、終わったものは初期化して戻し、余ったものは削除する |
| 配置場所 | `D:\WorkTree\<repo>\`(プロジェクトごとのフォルダ。ベースのクローンは `.base`、worktree は `wt-01`〜。普段の作業フォルダには触れない) |
| ブランチ名 | `feat/<内容>` |
| セッションの起動方法 | 基本は **commander スキル**(司令官モード)で起動する |
| CC Remote | **最初のフェーズから**デーモンに統合する(既存のゲームキャプチャ機能も移植) |
| 通知 | **Windows 通知 + PWA プッシュ(標準)、Discord(任意)** |
| commander | **汎用版をユーザースキルとして新規作成**。リポジトリに専用版(例: TomsLands)があればそちらを優先 |
| 承認 | commander セッションは **auto mode** で起動。auto mode でも承認が必要な操作は承認キューとスマホに上げる |
| PR の範囲 | **閲覧 + セッション連携操作**(作成・修正指示・マージ)。行単位レビューは GitHub に任せる |
| PR の表示対象 | **自分の PR + レビュー依頼 + セッション紐付き PR** |
| 動作環境 | Windows 11(このデスクトップ)。macOS は対象外 |

## 1. 目的

- 複数ウィンドウで Claude Code を並行運用する負担をなくし、1 画面で監視・操作・切替する
- セッションごとに独立した git worktree を割り当て、並行作業の衝突を防ぐ。プール化で即座に開始
- 各セッションの状態・サブエージェント・残トークン・ブランチ/PR を一覧で把握する
- 同じセッション群をスマホ(CC Remote / Tailscale 経由)からも操作する

## 2. 機能要件

### F1. セッション管理
| ID | 要件 |
|---|---|
| F1-1 | アプリからセッションを起動・停止・再起動・resume(PTY をデーモンが保持) |
| F1-2 | 各セッションの埋め込みターミナル(xterm.js)で直接入力 |
| F1-3 | セッションの命名、タブ/リスト切替 |
| F1-4 | 全セッション横断の承認キュー(許可プロンプトを検知してワンクリック承認/拒否) |
| F1-5 | 入力待ち・完了・エラー時の通知(手段は F6) |
| F1-6 | 外部(VS Code・ターミナル)で起動された claude セッションを読み取り専用で表示 |
| F1-7 | **既定の起動モードは commander**:`claude "/commander <指示>"` の形で起動する。通常モードも選択可能 |
| F1-8 | commander スキルを持たないリポジトリでは、汎用版 commander(ユーザースキル)を使う |

### F2. ステータス表示(ダッシュボード)
| ID | 要件 |
|---|---|
| F2-1 | セッション状態:`実行中` / `承認待ち` / `入力待ち` / `アイドル` / `エラー` / `停止` |
| F2-2 | 現在の作業:実行中ツールと対象、直近のメッセージ要約、経過時間 |
| F2-3 | サブエージェントを親子ツリー表示(種類・モデル・説明・状態・経過時間)。ネストにも対応。commander が並列起動したエージェントを一目で追えること |
| F2-4 | 残トークン:(a) プラン使用率(5時間/週次、リセット時刻) (b) セッションごとのコンテキスト使用率 |
| F2-5 | セッションごとの worktree・ブランチ・変更数・PR 状態 |

### F3. リポジトリ登録と Worktree プール
| ID | 要件 |
|---|---|
| F3-0 | GitHub の URL(https / `owner/repo` 形式)を入力すると `gh repo clone` で `D:\WorkTree\<repo>\.base` にクローンし、既定ブランチを自動判定して登録 |
| F3-1 | リポジトリごとに**待機中の worktree を常に 3 本**維持(設定で変更可) |
| F3-2 | 事前ウォームアップ:worktree 作成(detached HEAD)、fetch、依存インストール(`package.json` などを検出して自動判定。手動で上書き可) |
| F3-3 | 割当時に最新の `origin/<base>` から `feat/<内容>` ブランチを作成し、セッションを即座に起動。`<内容>` は最初の指示から英語の slug を自動生成(Haiku を使用、編集可) |
| F3-4 | **自動増設**:割当で待機数が 3 を下回ったら、バックグラウンドで補充する。総数の上限は設定可能(既定 10) |
| F3-5 | **終了時の初期化**:セッション終了時に「ブランチ保持」「PR 作成」「破棄」を選ぶ。その後 reset と clean を行い(依存ディレクトリは残して再インストールを省く)、待機状態に戻す |
| F3-6 | **自動縮小**:待機数が 3 を超えた分は、一定時間(既定 30 分)使われなければ削除する |
| F3-7 | プール状態(待機・使用中・準備中・初期化中・エラー)を表示 |

### F4. スマホ連携(CC Remote)
| ID | 要件 |
|---|---|
| F4-0 | **CC Remote を最初のフェーズからデーモンに統合**。既存の URL・PIN・PWA・承認バナー・タッチスクロール・ゲームキャプチャ(`/game/*`)をそのまま使える |
| F4-1 | セッション一覧・切替・承認・入力 |
| F4-2 | ダッシュボード(状態、サブエージェントツリー、残トークン)の簡易表示 |
| F4-3 | 新規セッション開始(リポジトリ選択 → プールから割当 → commander への初回指示) |
| F4-4 | 既存のセキュリティを維持:127.0.0.1 バインド、Tailscale serve、PIN |
| F4-5 | PR 一覧・CI 状態の確認、「この指摘を直して」指示、マージ承認 |

### F5. ブランチ / PR
#### F5-1. ブランチ
| ID | 要件 |
|---|---|
| F5-1-1 | 登録リポジトリのブランチ一覧(ローカル/リモート、base との ahead/behind、最終コミット、更新日時) |
| F5-1-2 | ブランチ ↔ worktree ↔ セッションの紐付けを表示 |
| F5-1-3 | 変更サマリー(diff stat)、コミット履歴、未 push コミット |
| F5-1-4 | base から遅れたブランチの検出と警告(rebase が必要なもの) |
| F5-1-5 | マージ済みブランチの一括クリーンアップ |

#### F5-2. PR
| ID | 要件 |
|---|---|
| F5-2-1 | PR 一覧(Open / Draft / Merged / Closed)。対象は自分の PR、レビュー依頼、セッション紐付きのもの |
| F5-2-2 | CI 状態、レビュー状態、マージ可否、コンフリクト |
| F5-2-3 | PR ↔ ブランチ ↔ worktree ↔ セッションの紐付け |
| F5-2-4 | 差分・説明・レビューコメントの閲覧 |
| F5-2-5 | 状態変化(CI 失敗、新しいコメント、マージ)の通知 |

#### F5-3. 操作
| ID | 要件 |
|---|---|
| F5-3-1 | セッションから PR を作成(push → `gh pr create`、説明は Claude が下書き) |
| F5-3-2 | レビューコメント / CI 失敗ログをセッションに転送して修正させる |
| F5-3-3 | 既存の PR・ブランチを新しいセッションとして開く(プールから worktree を割り当てて checkout) |
| F5-3-4 | マージ / クローズ(確認ダイアログ付き) |
| F5-3-5 | マージ後に worktree を初期化してプールに返却 |

### F6. 通知
| ID | 要件 |
|---|---|
| F6-1 | Windows トースト通知。クリックすると該当セッションを開く |
| F6-2 | PWA の Web Push(CC Remote のスマホアプリ宛て)。タップで該当セッションを開く |
| F6-3 | Discord Webhook(任意)。リポジトリやセッションごとに送り先チャンネルを設定可能 |
| F6-4 | 通知するイベントを選べる:承認待ち、入力待ち、完了、エラー、CI 失敗、レビューコメント、マージ |
| F6-5 | デスクトップで操作中のセッションのイベントはスマホと Discord に送らない(重複防止) |

## 3. 非機能要件
- UI を閉じてもセッションは継続(デーモンは常駐)。デーモンが再起動しても `--resume` で復帰できる
- 同時に約 10 セッションまで実用的に動作
- すべてローカルで完結(Claude・GitHub・選んだ通知サービス以外の外部サービスを使わない)
- 認証情報は `gh` の keyring と既存の CC Remote PIN を使う。通知用の Webhook URL などは `config.json` に保存し、会話やログに出さない
- 自動起動:既存の Watchdog の仕組み(スタートアップ + タスクスケジューラ)を継承

## 4. データ取得方式
| 対象 | ソース |
|---|---|
| セッション状態・現在のツール | グローバルな Claude Code hooks(`SessionStart`/`PreToolUse`/`PostToolUse`/`Notification`/`Stop`/`SessionEnd`)→ デーモンのローカル API に POST。予備として transcript JSONL を tail |
| サブエージェントの親子関係 | `SubagentStart`/`SubagentStop` hooks と `~/.claude/projects/<proj>/<session>/subagents/*.jsonl` |
| コンテキスト使用率 | transcript の `usage`、または statusLine の JSON |
| プラン使用率(5h/週) | statusLine スクリプトに渡される `rate_limits` をデーモンに転送(**実装時に要検証**) |
| ブランチ | ローカル git(ファイル監視 + 数秒間隔) |
| PR・CI | `gh pr list/view --json`、`gh run`(1〜2 分間隔のポーリングと手動更新) |

## 5. アーキテクチャ
```
┌──────────────── デスクトップ (Windows) ────────────────┐
│  Hub デーモン (Node.js, 常駐, 127.0.0.1:7860)            │
│   ├ PTY マネージャ (node-pty × N)                        │
│   ├ リポジトリ / Worktree プールマネージャ               │
│   ├ イベント収集 (hooks 受信 / JSONL tail / statusLine)  │
│   ├ Git/GitHub ウォッチャ (git, gh)                      │
│   ├ 通知ディスパッチャ                                   │
│   ├ ゲームキャプチャ (CC Remote から移植)                │
│   └ API: HTTP + WebSocket/SSE                            │
│        ▲                    ▲                            │
│   Electron アプリ        スマホ Web UI (PWA)             │
│   (デスクトップ UI)     ◄── Tailscale serve ── スマホ    │
└─────────────────────────────────────────────────────────┘
```
CC Remote の `server.js` をベースに、マルチセッション対応のデーモンへ発展させる。ポート・URL は既存のものを引き継ぐ。
